# 05 — 고객 여정 지도(CJM) 작성 방법론

> 페르소나가 **누구인지**를 정했다면, 고객 여정 지도는 그 사람이 **시간 순으로 무엇을 겪는지**를 펼친다.
> 선행 분석: [페르소나](../페르소나/) · [시장규모](../시장규모/)
> 작성일: 2026-08-10

## 고객 여정 지도란 무엇인가

고객 여정 지도(Customer Journey Map)는 고객이 브랜드·제품·서비스와 관계를 맺는 동안 겪는 경험 전체를 그림으로 옮긴 것이다. 핵심은 **소비자 관점**이다. 회사가 설계한 절차를 그리는 것이 아니라, 고객이 실제로 접하는 접점과 감정, 막히는 지점을 고객의 눈높이에서 잡아낸다.

인지, 조사, 구매, 구매 후까지 전체를 담을 수도 있고 조사 단계나 특정 제품 구매처럼 상호작용의 한 국면만 떼어 볼 수도 있다. 어느 쪽이든 목적은 같다. **개선이 필요한 곳을 찾아내고, 절차를 다듬어 고객 중심의 매끄러운 경험을 만드는 것.**

고객과의 상호작용은 영업·마케팅·제품 개발·지원처럼 여러 부서에 걸쳐 일어난다. 복잡한 상호작용이 지도 한 장에 한눈에 들어오기 때문에 CJM은 팀 사이의 협업 도구로도 쓰인다.

## 구매자 여정 지도와의 차이

두 지도는 비슷한 데이터를 쓰지만 범위가 다르다.

| 구분 | 다루는 범위 |
|---|---|
| **구매자 여정 지도** | 고객이 구매를 결정할 때까지 거치는 단계 |
| **고객 여정 지도** | 브랜드 지지 같은 구매 후 상호작용까지 포함한 더 넓은 라이프사이클 |

## 선형 퍼널에서 충성도 루프로

디지털 커머스 이전에는 매장을 둘러보거나 영업 담당자와 상담하는 한두 단계를 거쳐 구매가 끝났다. 그래서 브랜드 인지에서 구매까지 한 줄로 내려가는 **단일 판매 퍼널**이 여정을 그리는 주된 방식이었다.

지금은 웹사이트, 앱, 챗봇, 지원 센터, 매장까지 접점이 흩어져 있고 대부분의 잠재 고객이 구매 전에 지인에게 묻고 리뷰를 광범위하게 찾아본다. 2000년대 후반 McKinsey는 이 변화를 두고 소비자 여정이 한 줄이 아니라 **구매 후 경험과 적극적 평가가 동시에 일어나는 연속적인 순환**에 가깝다고 정리했다. 이상적으로는 그 순환이 이어지는 충성도 루프가 된다.

오늘날의 CJM은 이 루프를 닮는다. 여러 행동과 경험이 섞여 있고 그중 일부는 동시에 일어난다.

## CJM으로 얻는 것

| 이점 | 내용 |
|---|---|
| 고객 경험 개선 | 마찰이 생기는 자리를 찾아 만족도와 충성도를 끌어올린다 |
| 고객 유지율 향상 | 구매 후·지원 단계의 문제점을 짚어 이탈로 이어질 원인을 걸러낸다 |
| 팀 간 연계 | 부서마다 다르게 알고 있던 고객 경험을 하나의 그림으로 맞춘다 |
| 제품 개발 | 여정에서 나온 인사이트가 새 기능과 개선 항목이 된다 |
| 마케팅 효율 | 고객이 있는 자리에서 만나는 캠페인을 설계한다 |
| 고객 심리 이해 | 단계별 감정 반응에서 동기와 고충, 의사결정 과정을 읽는다 |
| 접점 우선순위 | 결정과 만족도에 가장 큰 영향을 주는 접점에 자원을 몰아준다 |
| 경쟁 우위 | 경쟁사가 비어 둔 자리나 덜 흔한 여정 경험을 찾아낸다 |

## 네 가지 유형

| 유형 | 그리는 대상 | 쓰임 |
|---|---|---|
| **현재 상태 맵** | 지금 실제로 일어나는 고객 행동 | 가장 흔한 형태. 현재 문제를 진단하고 개선 지점을 찾는다 |
| **미래 상태 맵** | 우리가 원하는 이상적인 여정 | 전략적 변화를 계획하고 개선 기준선을 세운다 |
| **일상 생활 맵** | 고객의 하루 전체와 그 안에서 제품이 놓이는 자리 | 기대와 과제의 더 넓은 맥락을 이해한다 |
| **서비스 청사진** | 여정 + 이면의 내부 절차·인력·시스템 | 나쁜 경험의 근본 원인을 찾는 데 가장 효과적이다 |

## 구성 요소

CJM은 요청한 데이터와 요청하지 않은 데이터를 섞어 만든다. 요청한 데이터는 고객 피드백, 만족도 설문, NPS처럼 고객이 직접 준 정보다. 요청하지 않은 데이터는 구매 내역, 이탈률, 페이지 체류 시간, 채팅·통화 기록처럼 일상적인 상호작용에서 쌓인다. 둘 중 하나만 쓰면 지도가 한쪽으로 기운다.

| 요소 | 담는 내용 |
|---|---|
| **여정의 단계** | 인지부터 구매 후 참여까지, 고객이 거치는 구분된 국면 |
| **고객 페르소나** | 세그먼트를 대표하는 가상의 데이터 기반 프로필 |
| **고객의 기대치** | 고객이 상호작용에 들고 오는 기준과 가정. 단계마다 달라진다 |
| **접점** | 각 단계에서 실제로 일어나는 구체적 상호작용 |
| **고객 행동** | 그 단계에서 고객이 하는 행동과 내리는 결정 |
| **감정** | 좌절·혼란·만족의 순간. 어디서 감정이 꺾이는지 |
| **채널** | 상호작용이 일어나는 플랫폼과 매체 |
| **인사이트** | 지도에서 도출한 판단. 놓친 연결과 개선 기회 |

### 여정의 일반적인 단계

| 단계 | 이 단계에서 일어나는 일 |
|---|---|
| 인지 | 필요, 브랜드, 특정 제품을 알게 된다. 마케팅으로 접했을 수도, 스스로 필요를 깨달았을 수도 있다 |
| 고려 | 선택지를 평가하고 조사한다. 리뷰를 읽고 지인에게 묻고 제품을 나란히 비교한다 |
| 결정 | 특정 제품이나 서비스를 사기로 정한다 |
| 온보딩 | 구매 후 실제로 쓰기 시작한다. 초점이 획득에서 유지로 넘어간다 |
| 충성도 | 확보한 고객이 지지자로 바뀐다. 사용량과 피드백으로 측정한다 |

**이 다섯 단계는 참고용 기본형이다.** 그대로 옮겨 쓰는 순간 지도가 서비스의 실제 여정과 어긋난다. 이유는 이 문서 맨 끝에 따로 적었다.

## 작성 절차

| 순서 | 하는 일 |
|---|---|
| 1. 명확한 목표 설정 | 무엇을 개선하려는지 먼저 정한다. 구매 절차 최적화인지, 이탈 원인 파악인지, 온보딩 개선인지. 이 단계에서 목표 KPI를 함께 잡는다 |
| 2. 고객 데이터 수집 | 피드백, 설문, 인터뷰, 채팅 기록, 지원 로그, 웹 분석을 여러 소스에서 모은다 |
| 3. 고객 페르소나 만들기 | 여정에 맥락을 주는 인물을 세운다. 세그먼트별로 나눈다 |
| 4. 핵심 단계 파악 | 이 서비스의 여정에서 실제로 구분되는 국면을 정의한다 |
| 5. 접점·채널 결정 | 고객이 어디서 어떻게 우리와 만나는지 짚는다 |
| 6. 감정과 고충 강조 | 단계마다 감정이 올라가고 내려가는 지점을 표시한다 |
| 7. 여정 검증 | 실제 고객이나 테스트로 지도가 맞는지 확인한다 |
| 8. 인사이트에 따라 조치 | 접점 커뮤니케이션을 강화하거나 자원을 옮기거나 기술에 투자한다 |

## 자주 걸리는 네 가지

| 과제 | 대응 |
|---|---|
| **데이터 품질** | 정확하고 오류 없는 데이터가 아니면 지도가 실제를 왜곡한다. 소스를 여러 개 쓰고 정기적으로 감사한다 |
| **과도한 단순화** | 옴니채널 환경의 여정은 복잡하다. 단순화하면 핵심 고충과 감정의 순간이 지워진다. 페르소나별로 여러 장을 만들거나 레이어를 쌓는다 |
| **내부 운영 누락** | 고객 쪽만 보면 병목과 비효율을 놓친다. 서비스 청사진을 만들거나 내부 팀과 함께 종속 관계를 확인한다 |
| **부서 간 단절** | 협업 없이 만든 지도는 다른 부서가 아는 사실을 놓친다. 공유 KPI를 세우고 함께 작성한다 |

## 이 저장소의 작성 규칙

사례 문서는 아래 형식을 지킨다.

1. **페르소나 블록과 시나리오 블록을 맨 위에 나란히 둔다.** 누구의 여정이고 어떤 상황인지가 지도보다 먼저 보여야 한다.
2. **단계는 그 페르소나에게 실제로 구분되는 국면으로 새로 정의한다.** 인지·고려·결정·온보딩·충성도를 기계적으로 쓰지 않는다.
3. **단계마다 다섯 칸을 채운다** — 고객 행동·접점 / 고객 생각 / 감정 / Pain Point / 개선 기회.
4. **고객 생각은 그 사람의 입말로 적는다.** 큰따옴표를 쓴다. 분석 언어로 바꾸면 감정이 사라진다.
5. **Pain Point는 한 문장으로 정확하게 끊는다.** "불편하다" 같은 서술은 Pain Point가 아니다. 무엇이 왜 막히는지가 들어가야 한다.
6. **감정 곡선을 함께 표시한다.** 어느 단계에서 꺾이는지가 개선 우선순위를 정한다.
7. **페르소나마다 별개의 지도를 만든다.** 한 장에 여러 사람을 겹치면 단계가 평균값으로 뭉개진다.

---

> ## ⚠️ 경고 — 단계는 매번 새로 정의해야 한다
>
> **고객 여정 지도는 항상 같은 단계로 그려지는 균일한 산출물이 아니다.**
>
> 인지 → 고려 → 결정 → 온보딩 → 충성도, 또는 문제 인식 → 탐색 → 의사결정 → 사용 → 유지 같은 단계 목록은 **어디서 가져와 채워 넣는 양식이 아니라, 매번 다시 정의해야 하는 결과물**이다. 서비스의 성격에 따라 여정의 핵심 단계는 완전히 달라진다.
>
> - 실시간 생중계 서비스에는 **'경기 시작 직전'과 '결정적 순간'** 처럼 몇 초 단위의 단계가 생긴다. 일반적인 구매 여정에는 없는 국면이다.
> - 무료로 먼저 쓰는 서비스에서는 **구매 결정 단계가 여정 중간이나 끝**으로 밀린다. 앞에 놓으면 실제 순서와 어긋난다.
> - 이미 이탈한 사용자를 다시 데려오는 여정에는 **'무관심 상태'와 '반신반의 확인'** 이 앞에 붙는다. 인지 단계로 뭉개면 왜 돌아오지 않는지 보이지 않는다.
> - B2B2C 구조에서는 **돈을 내는 쪽과 쓰는 쪽의 여정이 아예 다르다.** 한 장에 담으려 하면 둘 다 틀린다.
>
> 기본형을 그대로 쓴 지도는 만들기는 쉽지만 **아무것도 알려주지 않는다.** 이미 알고 있는 절차를 다시 적어 놓은 것에 불과하기 때문이다. 단계를 새로 정의하는 그 작업이 CJM에서 가장 중요한 판단이며, 그 판단이 틀리면 뒤의 다섯 칸을 아무리 정성껏 채워도 지도가 실제 여정을 가리키지 않는다.
>
> **양식을 채우기 전에, 이 서비스에서 고객이 실제로 넘는 문턱이 무엇인지부터 정하라.**
