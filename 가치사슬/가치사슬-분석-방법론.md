# 02 — 기업 내부 활동의 가치사슬 분석 (방법론)

> 포터의 5가지 힘이 **산업 밖**을 보는 도구라면, 가치사슬은 **기업 안**을 보는 도구다.

> 작성일: 2026-08-06

> **문서 안내**
> 원본을 옮기는 과정에서 표의 줄바꿈 지점마다 글자가 잘려 나가 문맥으로 복원했다(`Inbound` → `In/ound`, `• 고객 동의 기반…` → `• / - 동의 기반…`).
> 원본 질문은 핀테크·금융 플랫폼을 전제로 쓰여 있었으나, 어느 산업에나 그대로 던질 수 있도록 질문을 일반화했다. 금융 특화 표현이 필요하면 커밋 `1af98af`에 원본 표현이 남아 있다.

## 가치사슬 전체 구조

```mermaid
flowchart TB
    subgraph SUP["지원활동 Support Activities"]
        direction TB
        S1["기업 인프라 · Firm Infrastructure"]
        S2["인적자원 관리 · HRM"]
        S3["기술 개발 · Technology Development"]
        S4["조달·구매 · Procurement"]
    end

    subgraph PRI["주요활동 Primary Activities"]
        direction LR
        P1["투입·조달 물류<br/>Inbound"] --> P2["운영·생산<br/>Operations"] --> P3["산출·배송 물류<br/>Outbound"] --> P4["마케팅·영업<br/>Marketing & Sales"] --> P5["서비스<br/>Service"]
    end

    SUP -.->|"전 과정을 떠받침"| PRI
    PRI --> M["마진 Margin<br/><b>= 고객이 낸 값 − 활동 원가</b>"]

    classDef sup fill:#eef3fb,stroke:#4a6fa5,color:#111
    classDef pri fill:#fdf0d5,stroke:#c1121f,color:#111
    classDef margin fill:#d8f3dc,stroke:#2d6a4f,color:#111
    class S1,S2,S3,S4 sup
    class P1,P2,P3,P4,P5 pri
    class M margin
```

- **주요활동**은 가치가 실제로 만들어지고 고객에게 전달되는 흐름이다.
- **지원활동**은 그 흐름 전체를 떠받친다. 특정 단계에만 붙는 게 아니다.
- 각 활동을 **설계** 관점과 **개선** 관점 두 축으로 나눠 묻는 것이 이 방법론의 핵심이다. 처음 만들 때 던지는 질문과, 굴러가는 걸 고칠 때 던지는 질문은 다르다.

| 항목명(Activity) | 가치사슬 **설계**를 위한 질문 🏗️ | 가치사슬 **개선**을 위한 질문 🚀 |
| --- | --- | --- |
| **투입·조달 물류**<br/>Inbound Logistics<br/><br/>**핵심 투입자원·파트너 확보** | • 제품이나 서비스를 만드는 데 필요한 핵심 투입자원은 무엇인가?<br/>• 그 자원을 어떤 경로로 확보할 것인가 — 직접 생산, 매입, 제휴, 외부 서비스 중 무엇인가?<br/>• 공급자·파트너·유통 채널과 어떤 방식과 조건으로 연결할 것인가?<br/>• 어떤 자원을 자체 확보하고, 어떤 기능은 외부에 맡길 것인가?<br/>• 확보한 자원(원재료·데이터·권리·인력)을 어떻게 수집·정제·표준화할 것인가?<br/>• 공급자와 파트너가 우리와 거래할 유인은 무엇인가? | • 외부에서 들어오는 투입물의 품질·최신성·가용성을 어떻게 높일 것인가?<br/>• 특정 공급자나 특정 인프라에 대한 의존도를 줄일 수 있는가?<br/>• 공급 중단이나 장애에 대비한 대체 경로가 있는가?<br/>• 축적된 데이터와 경험을 다음 조달 판단에 다시 활용하고 있는가?<br/>• 조직이나 채널별로 중복 확보되는 자원을 줄일 수 있는가?<br/>• 최소한만 확보하는 것과 넉넉히 확보하는 것 사이의 균형을 어떻게 잡을 것인가? |
| **운영·생산**<br/>Operations<br/><br/>**투입을 고객 가치로 변환** | • 고객의 요청을 실제 가치로 바꾸는 핵심 처리 과정은 무엇인가?<br/>• 요청 접수 → 확인 → 처리 → 완료 → 결과 안내 흐름을 어떻게 설계할 것인가?<br/>• 각 단계에서 무엇을 표준화하고 무엇을 개별 대응할 것인가?<br/>• 품질·보안·안전·규정 준수를 공정 안에서 어떻게 수행할 것인가?<br/>• 수요가 급증해도 안정적으로 처리할 수 있는가?<br/>• 자동 처리와 사람의 판단 사이 경계를 어디에 둘 것인가? | • 처리 성공률과 완료 전환율을 어떻게 높일 것인가?<br/>• 고객이 처리 도중 이탈하는 단계와 원인은 무엇인가?<br/>• 처리시간, 오류율, 중단시간과 수작업 비율을 줄일 수 있는가?<br/>• 문제 감지율을 높이면서 정상 건의 오탐을 줄일 수 있는가?<br/>• 정산·분류·검수 같은 반복 업무를 자동화할 수 있는가?<br/>• 변경을 빠르게 반영하면서 운영 안정성을 함께 확보할 수 있는가? |

## 3. 5힘 분석과의 관계

두 도구는 겹치지 않는다. 5힘이 "이 산업이 돈이 되는 구조인가"를 묻는다면, 가치사슬은 "그 안에서 우리가 어디서 값을 만들고 어디서 새고 있는가"를 묻는다.

```mermaid
flowchart LR
    F["포터의 5가지 힘<br/>산업 <b>밖</b>의 구조"] -->|"어느 산업에서<br/>싸울지 결정"| D["전략"]
    V["가치사슬<br/>기업 <b>안</b>의 활동"] -->|"그 산업에서<br/>어떻게 이길지 결정"| D

    classDef out fill:#fdf0d5,stroke:#c1121f,color:#111
    classDef inn fill:#eef3fb,stroke:#4a6fa5,color:#111
    classDef dec fill:#d8f3dc,stroke:#2d6a4f,color:#111
    class F out
    class V inn
    class D dec
```

5힘 분석에서 "공급자의 힘이 세다"는 결론이 나왔다면, 가치사슬에서는 그 힘이 **어느 활동에 붙어 있는지**를 짚어야 한다. 투입 물류에 붙었는지, 조달·구매에 붙었는지, 아니면 기술 개발에 붙었는지에 따라 손댈 곳이 완전히 달라지기 때문이다.

각 분석에서는 위 범용 질문을 해당 산업의 언어로 바꿔 던졌다. 예를 들어 투입·조달 물류의 "핵심 투입자원은 무엇인가"는 OTT에서 중계권·라이선스·제작 인력을 묻는 질문이 되고, 온라인 커머스에서는 사입이냐 자체 제조냐를 묻는 질문이 된다. **질문의 뼈대는 같고 살만 바뀐다** — 이것이 이 질문표를 범용으로 두는 이유다.
